## E. Beyond the supplied examples

- **Cart row locking and upsert.** Cart edits and Checkout lock the same cart row before changing its items. Unique constraints and conflict handling give concurrent first edits one cart and one item per variant. PUT sets the requested absolute quantity.
- **Multi-service rollback and concurrent stock updates.** Checkout passes one transaction manager through catalog reads, order writes, stock deductions, movement records, and cart cleanup. Stock is updated only when the current balance covers the quantity. Deductions run in variant ID order. The PostgreSQL tests demonstrate rollback after a later deduction fails and one success when two checkouts compete for the last unit.
- **Order snapshots and money.** Checkout reads prices from the live catalog, checks line and order totals in integer BDT poisha, and stores address and item snapshots. Order history uses those stored values after price, catalog, or address edits.
- **Pagination and privacy-conscious instrumentation.** The order query combines ownership, a stable sort, and a paginated result. The middleware logs route templates and request IDs when responses finish. The timing interceptor observes only Checkout execution and sets `X-Response-Time`.
